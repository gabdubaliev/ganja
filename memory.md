## Архитектура

- `app/server.js` — HTTP-сервер.
  - Таблица маршрутов `[method, pattern, handler(params, url, body, user), access]`; `access` — право, список прав или `'any'`.
    Обработчик может быть async. `user` в обработчике — публичная запись: `stores` уже массив, `owner` — владелец ли.
  - Журнал действий: `AUDIT_LABELS` + `auditDetails`. Запросы с `dryRun` не пишутся.
- `app/db.js` — `createStore(file)`: вся бизнес-логика и миграции.
  - Колонки добавляются через `addColumns`.
  - Колонки таблиц, создаваемых ниже по `open()`, добавлять **в конце `open()`** — иначе на новой базе падает (`fines`, `shifts`).
  - Вложенные транзакции — через savepoints.
  - Одноразовые миграции помечаются в `settings`: `docs_migrated`, `rights_v2` … `rights_v5`.
  - Настройки на все магазины лежат в `mainStore`: `layout` (расположение), `secrets_key`, `anthropic_api_key`, `branches`.
- `app/roles.js` — `RIGHTS` (группы: Отчёты, Касса, Товары, Документы, Покупатели, Интернет-витрина, Персонал, Управление)
  и роли **owner** / admin / manager / cashier / storekeeper. `can(user, right)`, `rightsOf` (`timesheet.edit` даёт и `timesheet`).
  - `owner` — все права всегда (`rightsOf` → ALL), админ-панель, вход от имени сотрудника. Не урезается.
  - `admin` — права настраиваемые; по умолчанию все, кроме `audit` и `staff.passwords` (`OWNER_ONLY_BY_DEFAULT`).
  **Каждой новой функции — своя галочка** (владелец просит это всегда); при добавлении права — миграция для тех,
  у кого права настроены вручную, чтобы никто не потерял доступ.
- `app/auth.js` — подписанные HMAC-cookie `shop_session` (в подпись входит хеш пароля). Пароль и PIN — scrypt.
  - Вход от имени сотрудника: `actAsCookies` кладёт сессию сотрудника, сессия владельца бережётся в cookie `shop_owner`;
    `ownerOf(req)` — владелец, который смотрит; `returnCookies` — вернуться. `logoutCookie` чистит обе.
  - Лимит: 10 неверных попыток за 15 минут с одного IP.
  - Ключ в cookie: `id` (основной магазин) или `магазин-id` (филиал).
- Остальные модули сервера:
  - `invoice.js` — распознавание накладной по фото через Claude API;
  - `crm.js` — CRM, Instagram и WhatsApp через вебхуки Meta с проверкой `X-Hub-Signature-256`;
  - `shop-auth.js` — аккаунты покупателей витрины, коды подтверждения;
  - `sms.js` — провайдеры SMS (nikita / smspro, sms.ru, twilio, custom);
  - `notify.js` — SSE `/api/events` и Telegram;
  - `theme.js` — оформление (`theme.css`).
- **Фронтенд:** статический vanilla JS.
  - `public/index.html` — админ-панель; `kassa.html` — окно кассира; `shop.html` — витрина; `login.html`.
  - Разделы регистрируются как `views.name = { show, right }`, роутинг по `location.hash`.
  - `KASSA_TOO = {orders, tasks}` — разделы, которые есть и в окне кассы. Только в кассе: `mytimesheet`.
  - Модули админки: `products.js` (товары и карточка), `dashboard.js` (главная, расходы), `abc.js`, `receive.js` (приход по фото),
    `docs.js`, `timesheet.js`, `staff-time.js` (смены, штрафы, бонусы), `users.js`, `owner.js` (админ-панель владельца),
    `certificates.js`, `loyalty.js` (клиенты), `kpi.js`, `more.js` (меню «Ещё» и реестр разделов) и др.
  - Модули кассы: `pos.js` (чек, оплата, клиенты), `certificates-kassa.js`, `my-timesheet.js`, `sales.js`, `orders.js`, `tasks.js`.
  - `barcode.js` — штрихкод EAN-13 (в index.html и kassa.html); `labels.js` — печать этикеток.
  - Общие помощники в `common.js`: `salePrice`, `dateOnly`, `capitalizeWords` + `data-capitalize`, `finesListHtml`,
    `fineTipLines`, `actAsUser`, `applyLayout`, `catalog`, `RANGES`. Витрина (`shop.js`) common.js не подключает.

### Филиалы (несколько магазинов)

- У каждого магазина **своя база**: основной — `DB_FILE` (`data/shop.db`), филиалы — `data/branch-N.db`.
- Список филиалов хранится в настройке `branches` основной базы.
- `server.js`: `AsyncLocalStorage` + Proxy `store` / `notifier` / `crm` / `shopAuth` — каждый запрос работает в контексте своего магазина.
  - `contextOf(id)`, `branchList()`. Общие для всех магазинов настройки (ключ Claude API) — в `mainStore`.
  - Витрина `/shop*` и `/webhooks/*` всегда работают в основном магазине.
- **Владелец** — роль `owner` в основном магазине (`isOwner`: branch 1 + role owner): видит все магазины,
  выбор хранится в cookie `shop_branch`.
  - В филиале работает под записью-копией (`users.owner_shadow = 1`, роль owner).
- **Сотрудник** привязан к своему магазину.
  - `users.stores` (JSON) — в каких ещё магазинах может работать (там тоже копия с его ролью и правами).
  - `users.moved_to` — сотрудник переведён в другой магазин.
  - Email для входа один на все магазины; `staffDirectory` ищет его сначала в основной базе.
- Перемещение между магазинами: `branchLink.send` / `cancel` → `receiveTransfer` / `cancelTransfer`.
  Товар в целевом магазине ищется `findSameProduct`: штрихкод → код + название → название (коды у каждого магазина свои);
  если не найден — создаётся.
- Новый филиал копирует товары по именам колонок (`PRAGMA table_info`), без связи с поставщиками.

| `staff.passwords` | пароли и PIN сотрудников, их последний вход и IP | только владелец (галочкой — администратору) |
| `audit` | журнал действий | только владелец (галочкой — администратору) |
| `customers.create` | искать и заводить покупателей на кассе (ФИО, телефон, карта, ДР, пол) | кассир, управляющий |
| `certificates.sell` | продавать сертификаты на кассе | кассир, управляющий |
| `certificates.accept` | принимать сертификаты в оплату | кассир, управляющий |
| `certificates` | раздел «Сертификаты»: список, история, блокировка, срок | управляющий |
| `orders.payment` | подтверждать оплату заказов с витрины («Оплата поступила» / «не найдена») | кассир, управляющий (миграция `rights_v6`: у кого `orders`) |
| `print.design` | конструктор чеков и этикеток | администратор (миграция `rights_v7`: у кого `design`/`settings`) |
| `reports.stock` | товарный отчёт, остатки на дату, неликвиды | управляющий (миграция `rights_v8`: у кого `kpi`/`dashboard`/`abc`) |
| `automation` | автоотчёты и автоуценка: настройка и запуск | администратор (миграция `rights_v8`: у кого `settings`) |
| `reports.money` | ДДС и прибыль по месяцам | управляющий (миграция `rights_v9`: у кого `finance`/`accounts`) |
| `certificates.manage` | создавать (и бесплатно), менять сумму и срок, удалять сертификаты | только владелец и администратор |

У администратора по умолчанию все права, кроме `audit` и `staff.passwords`; у владельца — все всегда.

Миграции для тех, у кого права настроены вручную (новые галочки добавляются по смыслу, чтобы никто не потерял доступ):
- `rights_v2`: `dashboard` → `finance`, `abc`; `kpi` → `abc`; `arrivals` → `receive.photo`; `products` → `products.history`; всем — `mytimesheet`;
- `rights_v3`: `salary` → `bonuses`;
- `rights_v4`: `pos` → `customers.create`;
- `rights_v5`: `pos` → `certificates.sell`, `certificates.accept`; `customers` → `certificates`;
- `rights_v6`: `orders` → `orders.payment`;
- `rights_v7`: `design` или `settings` → `print.design`;
- `rights_v8`: `kpi`/`dashboard`/`abc` → `reports.stock`; `settings` → `automation`;
- `rights_v9`: `finance` или `accounts` → `reports.money`.

## Как проверять

- Тестовые базы и скрипты Playwright — в scratchpad, не в репозитории. Базу с сотрудниками и входом проверять,
  запуская сервер с `ADMIN_EMAIL`/`ADMIN_PASSWORD` и входя через `POST /api/login` в контексте Playwright.
- Распознавание накладных — с заглушкой: свой HTTP-сервер и `ANTHROPIC_BASE_URL=http://127.0.0.1:PORT`.
- Логику в базе (сертификаты, расходы, зарплата) удобно проверять node-скриптом: `createStore(копия базы)` и вызовы методов.
- `/api/customers?q=` (раздел «Клиенты») и `/api/customers/search` (касса) — разные поиски.
- Копировать базу только через `VACUUM INTO`: простой `cp` без `-wal` теряет данные.
- Chromium уже установлен (`require('playwright')`).
- Скриншоты обязательно смотреть глазами: так находились коллизии CSS-классов и id.
  - Примеры: `.pos`, `.task`, `.variant-options`, `#fx-amount` (был дважды — поле не заполнялось).
  - Новым блокам давать уникальные классы и id.
- Глобальные стили таблиц (`th, td { text-align: right }`, `table { min-width: 860px }`) нужно перебивать в новых таблицах.
- `pkill -f server.js` в той же команде, что `git`, обрывает shell с кодом 144 — запускать отдельной командой.

## Не сделано / идеи

- Распознавание накладной реальным ключом не проверялось (в песочнице ключа нет) — только с заглушкой API.
- Документ «Возврат продажи» пока не вычитается из выручки в отчётах (уменьшает только остаток счёта).
- Себестоимость при отмене закупки откатывается, только если товар потом не закупали.
- Витрина и онлайн-заказы есть только у основного магазина.
- Повторяющиеся задания (каждый день) не реализованы.
- Отправка в Meta, SMS и Telegram из песочницы не проверялась (только на заглушках).
- Списания в чистой прибыли считаются по себестоимости (с расходами), а не по цене закупки.
- Скидка товара не применяется к документу «Продажа» задним числом: цена строки берётся со скидкой при добавлении.
- Право `expenses` без `finance` не даёт места, где вносить расходы (блок расходов — на главной под `finance`).
- Скрытие раздела в админ-панели не закрывает API — закрывают права («Кому доступно»).
- Перетаскивание блоков мышью не сделано — порядок стрелками ↑↓.
- Сертификаты: продаются только на кассе или в разделе «Сертификаты»; на витрине их купить нельзя. Сертификат продаётся одним
  способом оплаты (смешанная оплата есть на сервере, в окне кассы — нет). Изменение суммы сертификата деньги на счетах не меняет.
- Касса разрешает продавать товар в минус по остатку (было и раньше).
