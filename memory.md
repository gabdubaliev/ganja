  Порт 3000 был занят (EADDRINUSE), поэтому используется 3001.

  - Владельцу сказано никому не передавать пароли root и cctld.
- **Требования:** Node ≥ 22.13, встроенный `node:sqlite`, без npm-зависимостей.

## Архитектура

- `app/server.js` — HTTP-сервер.
  - Таблица маршрутов `[method, pattern, handler(params, url, body, user), access]`; `access` — право, список прав или `'any'`.
  - Журнал действий: `AUDIT_LABELS` + `auditDetails`. Запросы с `dryRun` не пишутся.
- `app/db.js` — `createStore(file)`: вся бизнес-логика и миграции.
  - Колонки добавляются через `addColumns`.
  - Колонки таблиц, создаваемых ниже по `open()`, добавлять **в конце `open()`** — иначе на новой базе падает (`fines`, `shifts`).
  - Вложенные транзакции — через savepoints.
- `app/roles.js` — `RIGHTS` (группы: Отчёты, Касса, Товары, Документы, Покупатели, Интернет-витрина, Персонал, Управление)
  и роли admin / manager / cashier / storekeeper. `can(user, right)`, `rightsOf`.
- `app/auth.js` — подписанные HMAC-cookie `shop_session` (в подпись входит хеш пароля). Пароль и PIN — scrypt.
  - Лимит: 10 неверных попыток за 15 минут с одного IP.
  - Ключ в cookie: `id` (основной магазин) или `магазин-id` (филиал).
- Остальные модули сервера:
  - `crm.js` — CRM, Instagram и WhatsApp через вебхуки Meta с проверкой `X-Hub-Signature-256`;
  - `shop-auth.js` — аккаунты покупателей витрины, коды подтверждения;
  - `sms.js` — провайдеры SMS (nikita / smspro, sms.ru, twilio, custom);
  - `notify.js` — SSE `/api/events` и Telegram;
  - `theme.js` — оформление (`theme.css`).
- **Фронтенд:** статический vanilla JS.
  - `public/index.html` — админ-панель; `kassa.html` — окно кассира; `shop.html` — витрина; `login.html`.
  - Разделы регистрируются как `views.name = { show, right }`, роутинг по `location.hash`.
  - `KASSA_TOO = {orders, tasks}` — разделы, которые есть и в окне кассы.

### Филиалы (несколько магазинов)

- У каждого магазина **своя база**: основной — `DB_FILE` (`data/shop.db`), филиалы — `data/branch-N.db`.
- Список филиалов хранится в настройке `branches` основной базы.
- `server.js`: `AsyncLocalStorage` + Proxy `store` / `notifier` / `crm` / `shopAuth` — каждый запрос работает в контексте своего магазина.
  - `contextOf(id)`, `branchList()`.
  - Витрина `/shop*` и `/webhooks/*` всегда работают в основном магазине.
- **Владелец** — admin основного магазина: видит все магазины, выбор хранится в cookie `shop_branch`.
  - В филиале работает под записью-копией (`users.owner_shadow = 1`, роль admin).
- **Сотрудник** привязан к своему магазину.
  - `users.stores` (JSON) — в каких ещё магазинах может работать (там тоже копия с его ролью и правами).
  - `users.moved_to` — сотрудник переведён в другой магазин.
  - Email для входа один на все магазины; `staffDirectory` ищет его сначала в основной базе.
- Перемещение между магазинами: `branchLink.send` / `cancel` → `receiveTransfer` / `cancelTransfer`.
  Товар в целевом магазине ищется по штрихкоду, коду или названию; если не найден — создаётся.

## Что сделано (по порядку)

1. **Основа.**
   - Товары: модификации (цвет, размер), генератор вариантов, штрихкоды EAN-13 с префиксом 20, этикетки для Xprinter XP-365B 58×40, импорт из Excel.
   - Категории: регистр кириллицы сравнивается в JS, аватарки категорий.
   - Касса, продажи, приход, покупатели и бонусы (лояльность, скидка в день рождения).
2. **Роли и права** — галочками, у каждого сотрудника можно настроить свой набор.
   - Окно кассира `kassa.html`: продажа, мои чеки, онлайн-заказы, задания, фото товаров.
3. **KPI и зарплата** (выплатные периоды 1–15 и 16–конец месяца):
   - ставка за выход, оклад, процент от продаж, план и бонус за план, штрафы, разовые бонусы;
   - ручные исправления сумм ведомости за период (`pay_overrides`); право «Зарплата».
4. **Главная:** выручка, себестоимость, прибыль, маржа (за вычетом комиссии банков), топ товаров и сотрудников.
   - Блок «Касса сейчас»: открытые смены, наличные и безнал.
   - Карточка товара открывается кликом; итоги остатков по себестоимости и по цене продажи.
5. **Журнал продаж:** удаление одного, нескольких или всех чеков (отдельное право), журнал действий, современный дизайн.
6. **CRM** (Instagram, WhatsApp), **витрина** с аккаунтами покупателей (вход по телефону и паролю, коды по SMS),
   конструктор витрины.
7. **Оплата.**
   - Свои способы оплаты (МБАНК, Оптима…) с доступом по сотрудникам; смешанная оплата (`sale_payments`).
   - Комиссия банка в % на способ оплаты.
   - Скидки кассира: на строку, группу или чек, в % / сомах / новой ценой, с пределом в карточке сотрудника.
   - Цену в чеке считает сервер; клиентскую цену принимает только выдача заказа (`trustPrices`).
8. **Персонал:**
   - табель в стиле Excel (дни, заработок за день, итоги по периодам, CSV);
   - задания (день / неделя / месяц / к дате → «Выполнено» → проверка: принять или вернуть).
9. **Касса:**
   - право «Видеть остатки» (без него сервер отдаёт `stock: null`);
   - быстрая смена кассира по PIN (4–6 цифр, простые запрещены), чек переносится к новому кассиру.
10. **Документы** с переключателем «Не проведён / ✓ Проведён»: продажа, закупка, возврат продажи, оприходование,
    списание, инвентаризация, перемещение (таблицы `docs`, `doc_items`).
    - Проведение меняет остатки (продажа создаёт чек); отмена проведения возвращает всё как было.
    - Отмена проведения — отдельное право `docs.unpost`.
    - Старые приходы и складские документы перенесены (`docs_migrated`).
11. **Прочее:**
    - Клиенты, Поставщики (`suppliers`), Сотрудники.
    - **Счета:** способы оплаты как места, где лежат деньги; начальный остаток; внесение, изъятие, перевод (`account_ops`).
    - **Кассы:** `registers`, `shifts.register_id`.
    - **Магазины** (филиалы).
12. **Привязка сотрудников к магазинам:** свой магазин, перевод (нельзя при открытой смене),
    «может работать также в», список «Все магазины» у владельца.

13. **Карточка товара и чистая прибыль:**
    - Вся строка в «Товарах» — кнопка, открывает карточку с разделами: Информация (создан, последнее поступление,
      код, штрихкод, артикул, поставщик), Цены и скидки, Склад (остатки во всех магазинах), История (движение с датами).
      Сверху «Редактировать» — диалог со всеми полями.
    - Новые поля товара: `purchase` (цена закупки — чисто товар), `article`, `supplier_id`, `discount` (% скидки).
      `cost` — себестоимость = закупка + расходы на единицу. Наценка и маржинальность — от цены закупки (так хочет владелец).
    - Код товара присваивается сам (`nextCode`: 00001, 00002…), пустые коды заполняются при каждом открытии базы (`fillCodes`).
    - Скидка товара применяется сервером в `createSale` (не при `trustPrices`), касса и витрина показывают цену со скидкой (`salePrice`).
    - Закупка пересчитывает `purchase` средневзвешенно, `cost` сдвигается на ту же величину (наценка расходов сохраняется);
      отмена закупки возвращает обе (`doc_items.prev_purchase`). Поставщик закупки ставится товару, если не был указан.
    - `sale_items.purchase` — цена закупки в момент продажи. Главная, хиты и KPI считают прибыль от неё.
    - Главная (7 плиток): Выручка, Расходы, Цена закупки, Чистая прибыль, Средний чек, Чеки, Глубина чека (товаров в чеке).
      Валовой прибыли нет — владелец просил убрать.
    - Блок «Расходы и чистая прибыль»: выручка − цена закупки − зарплата (по сотрудникам, раскрывается) − постоянные
      расходы − разовые − списания. `finance()` доводит период до конца дня, чтобы оклад и аренда за сегодня были за целый день.
    - Зарплата — из `kpi()`: ставка × выходы (двое на смене — две ставки), оклад за долю месяца, свой % от продаж, бонусы − штрафы.
    - Постоянные расходы (`recurring_expenses`: аренда, таргет — заводит владелец): сумма в месяц делится на число дней
      этого месяца (`dayShare`), каждый день периода — своя доля; `since` — с какого дня.
    - Разовые расходы — `expenses`, право `expenses`; расход со счёта уменьшает остаток счёта.
    - Остатки в других магазинах: `findSameProduct` — штрихкод, затем код + название, затем название (коды в магазинах свои).
    - Новый филиал копирует товары по именам колонок, без связи с поставщиками.

14. **Правка табеля** (право `timesheet.edit`, даёт и просмотр табеля; у управляющего включено):
    - Выбор дней кликом: ячейка, вся строка (имя), весь столбец (число); выбор остаётся после действия, чтобы
      применить несколько действий к одной группе. Действия: рабочий день, выходной, по сменам, сумма за день, цвет, сбросить.
    - Хранится в `timesheet_marks (user_id, day 'ГГГГ-ММ-ДД')`: status work/off, amount, color, note.
    - `kpi()` учитывает отметки: work — выход есть, off — выхода нет; amount заменяет расчёт дня (ставка + % выручки дня).
      Поэтому меняются и зарплата к выплате, и расходы на главной. API: `PUT /api/timesheet/marks`.
    - После действия выбор дней снимается сам (просил владелец).
15. **Мой табель** в окне кассы (`#mytimesheet`, `my-timesheet.js`, рядом с «Заказами»): сотрудник видит только свою
    строку за месяц календарём и итоги к выплате 1–15 / 16–конец; только просмотр. API `GET /api/my-timesheet` (любой вошедший).

16. **ABC / XYZ анализ** («Ещё» → «Отчёты», `#abc`, `abc.js`, право `kpi` или `dashboard`) — пробный вариант,
    владелец решит, где ему место. Только полные недели/месяцы (8/13 недель, 6/12 месяцев).
    - ABC по выручке/прибыли/количеству: A — до 80% накопленной доли, B — до 95%, C — остальное.
    - XYZ — коэффициент вариации продаж по полным неделям (месяцам) после даты заведения товара: X ≤ 20%, Y ≤ 40%, Z — больше
      или меньше 3 точек. Границы меняются в «Границы групп».
    - Матрица 3×3 с советами и деньгами в остатке, таблица со спарклайнами, CSV. API `GET /api/reports/abc`.

    - Матрица (13 полных недель по выручке) стоит и на главной перед «Товары и остатки» (`renderHomeAbc`); клетка открывает `#abc`.
17. **Приход по фото накладной** («Ещё» → «Документы», `#receive`, `receive.js`, право `arrivals`):
    - Фото → `invoice.js` → Claude API (`claude-opus-5-5`, structured outputs `output_config.format` json_schema,
      `fallbacks: "default"`). Прямой HTTPS без SDK — программа без npm-зависимостей. Ключ: `ANTHROPIC_API_KEY`
      или настройка `anthropic_api_key` в основной базе (вводит администратор на странице). `ANTHROPIC_BASE_URL` — для тестов.
    - `matchInvoiceLines`: штрихкод → артикул/код → название → похожее название (общие слова, сокращения, без единиц, ≥ 60%).
    - `receiveInvoice`: цена × курс = закупка в сомах; доп. расходы делятся по строкам пропорционально сумме → себестоимость;
      наценка % или сумма — от закупки (галочка — от себестоимости); новые товары заводятся; документ «Закупка» проводится;
      себестоимость после проведения = средняя закупка + доп. расход партии на единицу; доп. расходы пишутся в `expenses`.
      Последний курс — настройка `usd_rate`. Черновик экрана хранится в localStorage (`rcDraft`).
    - Реальным ключом не проверялось (в песочнице ключа нет) — проверено с заглушкой API.

18. **Документы по разделам и новые права:**
    - В разделе вида (Инвентаризации, Списания…) — своя большая кнопка («📋 Начать инвентаризацию», «🗑️ Новое списание»…),
      и в пустом списке тоже. Инвентаризация начинается с выбора: все товары / категория / сканировать по одному (`#inv-start-dialog`).
      В «Товарах» групповые кнопки «Инвентаризация» и «Списать» для выбранных.
    - Новые галочки: `finance` (расходы и чистая прибыль на главной), `abc`, `products.history`, `receive.photo`, `mytimesheet`
      (плюс ранее `expenses`, `timesheet.edit`). Миграция `rights_v2`: у кого права настроены вручную — новые добавлены по смыслу.

## Как проверять

- Тестовые базы и скрипты Playwright — в scratchpad, не в репозитории.
- Копировать базу только через `VACUUM INTO`: простой `cp` без `-wal` теряет данные.
- Chromium уже установлен (`require('playwright')`).
- Скриншоты обязательно смотреть глазами: так находились коллизии CSS-классов.
  - Примеры: `.pos`, `.task`, `.variant-options`.
  - Новым блокам давать уникальные классы.
- `pkill -f server.js` в той же команде, что `git`, обрывает shell с кодом 144 — запускать отдельной командой.

## Не сделано / идеи

- Документ «Возврат продажи» пока не вычитается из выручки в отчётах (уменьшает только остаток счёта).
- Себестоимость при отмене закупки откатывается, только если товар потом не закупали.
- Витрина и онлайн-заказы есть только у основного магазина.
- Повторяющиеся задания (каждый день) не реализованы.
- Отправка в Meta, SMS и Telegram из песочницы не проверялась (только на заглушках).
- Деплой на montshop.kg ждёт IP сервера от владельца.
- Списания в чистой прибыли считаются по себестоимости (с расходами), а не по цене закупки.
- Скидка товара не применяется к документу «Продажа» задним числом: цена строки берётся со скидкой при добавлении.
