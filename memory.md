## Архитектура

- `app/server.js` — HTTP-сервер.
  - Таблица маршрутов `[method, pattern, handler(params, url, body, user), access]`; `access` — право, список прав или `'any'`.
    Обработчик может быть async. `user` в обработчике — публичная запись: `stores` уже массив, `owner` — владелец ли.
  - Журнал действий: `AUDIT_LABELS` + `auditDetails`. Запросы с `dryRun` не пишутся.
- `app/db.js` — `createStore(file)`: вся бизнес-логика и миграции.
  - Колонки добавляются через `addColumns`.
  - Колонки таблиц, создаваемых ниже по `open()`, добавлять **в конце `open()`** — иначе на новой базе падает (`fines`, `shifts`).
  - Вложенные транзакции — через savepoints.
  - Одноразовые миграции помечаются в `settings`: `docs_migrated`, `rights_v2`, `rights_v3`.
  - Настройки на все магазины лежат в `mainStore`: `layout` (расположение), `secrets_key`, `anthropic_api_key`, `branches`.
- `app/roles.js` — `RIGHTS` (группы: Отчёты, Касса, Товары, Документы, Покупатели, Интернет-витрина, Персонал, Управление)
  и роли **owner** / admin / manager / cashier / storekeeper. `can(user, right)`, `rightsOf` (`timesheet.edit` даёт и `timesheet`).
  - `owner` — все права всегда (`rightsOf` → ALL), админ-панель, вход от имени сотрудника. Не урезается.
  - `admin` — права настраиваемые; по умолчанию все, кроме `audit` и `staff.passwords` (`OWNER_ONLY_BY_DEFAULT`).
  **Каждой новой функции — своя галочка** (владелец просит это всегда); при добавлении права — миграция для тех,
  у кого права настроены вручную, чтобы никто не потерял доступ.
- `app/auth.js` — подписанные HMAC-cookie `shop_session` (в подпись входит хеш пароля). Пароль и PIN — scrypt.
  - Вход от имени сотрудника: `actAsCookies` кладёт сессию сотрудника, сессия владельца бережётся в cookie `shop_owner`;
    `ownerOf(req)` — владелец, который смотрит; `returnCookies` — вернуться. `logoutCookie` чистит обе.
  - Лимит: 10 неверных попыток за 15 минут с одного IP.
  - Ключ в cookie: `id` (основной магазин) или `магазин-id` (филиал).
- Остальные модули сервера:
  - `invoice.js` — распознавание накладной по фото через Claude API;
  - `crm.js` — CRM, Instagram и WhatsApp через вебхуки Meta с проверкой `X-Hub-Signature-256`;
  - `shop-auth.js` — аккаунты покупателей витрины, коды подтверждения;
  - `sms.js` — провайдеры SMS (nikita / smspro, sms.ru, twilio, custom);
  - `notify.js` — SSE `/api/events` и Telegram;
  - `theme.js` — оформление (`theme.css`).
- **Фронтенд:** статический vanilla JS.
  - `public/index.html` — админ-панель; `kassa.html` — окно кассира; `shop.html` — витрина; `login.html`.
  - Разделы регистрируются как `views.name = { show, right }`, роутинг по `location.hash`.
  - `KASSA_TOO = {orders, tasks}` — разделы, которые есть и в окне кассы. Только в кассе: `mytimesheet`.
  - Модули: `products.js` (товары и карточка), `dashboard.js` (главная, расходы), `abc.js`, `receive.js` (приход по фото),
    `docs.js`, `timesheet.js`, `my-timesheet.js` (касса), `staff-time.js` (смены, штрафы, бонусы), `kpi.js` и др.
  - Общие помощники в `common.js`: `salePrice`, `dateOnly`, `finesListHtml`, `fineTipLines`, `catalog`, `RANGES`.

### Филиалы (несколько магазинов)

- У каждого магазина **своя база**: основной — `DB_FILE` (`data/shop.db`), филиалы — `data/branch-N.db`.
- Список филиалов хранится в настройке `branches` основной базы.
- `server.js`: `AsyncLocalStorage` + Proxy `store` / `notifier` / `crm` / `shopAuth` — каждый запрос работает в контексте своего магазина.
  - `contextOf(id)`, `branchList()`. Общие для всех магазинов настройки (ключ Claude API) — в `mainStore`.
  - Витрина `/shop*` и `/webhooks/*` всегда работают в основном магазине.
- **Владелец** — роль `owner` в основном магазине (`isOwner`: branch 1 + role owner): видит все магазины,
  выбор хранится в cookie `shop_branch`.
  - В филиале работает под записью-копией (`users.owner_shadow = 1`, роль owner).
- **Сотрудник** привязан к своему магазину.
  - `users.stores` (JSON) — в каких ещё магазинах может работать (там тоже копия с его ролью и правами).
  - `users.moved_to` — сотрудник переведён в другой магазин.
  - Email для входа один на все магазины; `staffDirectory` ищет его сначала в основной базе.
- Перемещение между магазинами: `branchLink.send` / `cancel` → `receiveTransfer` / `cancelTransfer`.
  Товар в целевом магазине ищется `findSameProduct`: штрихкод → код + название → название (коды у каждого магазина свои);
  если не найден — создаётся.
- Новый филиал копирует товары по именам колонок (`PRAGMA table_info`), без связи с поставщиками.

1. **Основа.**
   - Товары: модификации (цвет, размер), генератор вариантов, штрихкоды EAN-13 с префиксом 20, этикетки для Xprinter XP-365B 58×40, импорт из Excel.

2. **Роли и права** — галочками, у каждого сотрудника можно настроить свой набор.
   - Окно кассира `kassa.html`: продажа, мои чеки, онлайн-заказы, мой табель, задания, фото товаров.
3. **KPI и зарплата** (выплатные периоды 1–15 и 16–конец месяца):

   - ручные исправления сумм ведомости за период (`pay_overrides`); право «Зарплата».
4. **Главная (ранняя версия):** выручка, прибыль, топ товаров и сотрудников, блок «Касса сейчас», таблица «Товары и остатки».

5. **Журнал продаж:** удаление одного, нескольких или всех чеков (отдельное право), журнал действий.

   - Комиссия банка в % на способ оплаты.
   - Скидки кассира: на строку, группу или чек, в % / сомах / новой ценой, с пределом в карточке сотрудника.
   - Цену в чеке считает сервер; клиентскую цену принимает только выдача заказа и документ «Продажа» (`trustPrices`).

Миграция `rights_v2` добавила новые права тем, у кого права настроены вручную, по смыслу
(`dashboard` → `finance`, `abc`; `kpi` → `abc`; `arrivals` → `receive.photo`; `products` → `products.history`; всем — `mytimesheet`).
